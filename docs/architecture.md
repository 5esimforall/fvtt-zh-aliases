# 三插件架构

## 共享什么，隔离什么

中文显示名与英文查找名之间的证据可供多个自动化来源使用，但各提供方的候选目录、查找范围和注册入口不同。因此三个插件共享解析过程，不共享一张输出映射表。产品目标见 [设计](../DESIGN.md)，安装、命令和报告字段见 [README](../README.md)。

| 插件 | 输入 | 输出与外部副作用 |
| --- | --- | --- |
| `truesight` | Quick Insert 可见索引、来源、客户端审核、可选译表与原名、适配层候选 | 审核成员关系、只读名称快照、计划与诊断；仅保存自身客户端审核 |
| `cpr-zh-aliases` | 基座快照、CPR 配置与宏名称、既有映射 | 将完整计划中的新增名称写入本客户端 `CONFIG.chrisPremades.renamedItems` |
| `gps-zh-aliases` | 基座快照、GPS 合集目录、CPR 的 GPS 集成模式 | 包装 Medkit 调用的查找入口，仅补回原结果缺少的 GPS 候选 |

两个名称适配只导入自己目录中的文件，通过 `game.modules.get("truesight").api.names` 调用基座。名称层没有 CPR/GPS 依赖或协议字段；聚类层沿用原有索引自动化标记作为展示元数据，不调用提供方代码。CPR 标识、宏表、GPS 合集清单和来源模式均在各适配插件内解释。三个发行包可以独立解压，两个适配插件只依赖基座和各自实际需要的上游模块。

## 基座接口与快照

基座在 Foundry `init` 发布 `apiVersion: 1`，分为 `catalog`、`names`、`sources` 三个命名空间。目录与审核 API 见 [Truesight 说明](../modules/truesight/README.md)。以下函数位于 `api.names`，其 `apiVersion` 也为 1。该版本是接口版本，不是插件发行版本。适配层只接受兼容的接口版本，不支持时保留原查找。

- `loadCorpus({fields})`：使用当前 Foundry 客户端读取快照；`readCorpus(...)` 是可注入数据源的同一加载过程，用于测试。每次快照并发读取至多八个合集，不在两个适配器之间复用可变状态。
- `collectNamePairs(...)`：归一译表名称对，保留来源及可确认的类型、规则代际。ID 键使用本次快照恢复原名；缺少上下文的证据保持未限定，不凭显示名猜代际。
- `itemGroups(...)`：仅消费聚类层返回的有效审核成员关系，记录普通名称证据；适配层可传入额外证据提取函数。目录不可用或形状不符时失败，不创建替代分组。
- `planAliases({pairs, lookupNames, existingAliases, groups, scope})`：纯计算，返回 `{aliases: Map, report}`；不修改参数、名称表或文档。

作用域由适配层指定。`scope: null` 要求所有同名键全局一致；指定 `{rules, type, types}` 时，先排除已知不属于该作用域的证据和成员。未限定证据仍参与歧义检查。共享字段 `lookupNames` 表示额外的已确认查找名，不替代系统的 `system.identifier` 或提供方自己的标识。

计划先收集独立证据，再检查共用显示名的组。一个组的推断不会成为另一个组的新证据。已命中的完整双语名、明确原名和既有映射都保留来源；未命中的双语弱推测不能制造冲突，也不能单独发布别名。

## CPR 适配

CPR 适配在 `cprReady` 后读取 CPR 实际配置的合集 ID，尊重可见性与 `thirdParty` 设置。通过 CPR 宏表解释 `flags.chris-premades.info.identifier`，这与 `system.identifier` 是不同字段。CPR 动作译表也由该适配层追加到共同译表来源，而非写死在基座中。

CPR 的出口是一张全局显示名表，因此计划使用全局作用域。所有输入加载和计划生成完成后才注册，已有映射及原生名称保留。初始化失败时不会写入部分计划。停用并重载撤去本插件提供的新增映射；`api.refresh()` 撤下自己发布的旧键再重建，`api.stop()` 撤回自己仍持有的键；其他插件后续改写的键保留。审核通知自动刷新，异步过期构建不再写入。

## GPS 适配

本机 CPR 1.5.49 的 source map 显示，Medkit 通过公开的 `compendiumUtils.getAllAutomations` 查询候选。该函数内部按来源分别调用查找函数；GPS 分支读取其闭包中的目录，而不是 CPR 的 `renamedItems`。只替换公开对象上的 `getGPSAutomation`，无法改变该内部闭包调用。

GPS 适配因此包装公开对象的 `getAllAutomations`，不导入或修改 CPR 的私有集成目录：

1. 原样执行原生查找，原生 GPS 候选存在时直接返回。
2. 根据提供方启用状态、类型、规则代际和当前 GPS 集成模式，查询独立的名称计划。
3. 只在计划有唯一英文名时，以只读名称视图重试原生入口。原物品、嵌套数据和方法接收者保持原有对象，未调用文档更新或自动化应用。
4. 只收取重试结果中的 `gambits-premades` 来源，保留原有其他提供方结果，再按原生返回的优先级排序。版本、文档 UUID 和候选选择仍由原入口决定。

GPS 的目录按 CPR 集成使用的合集清单和 `gambitPremades` 模式读取，规则代际按其合集后缀区分。模式变化采用新计划，已有原生结果始终优先。适配层不修改官方 aliases；它们若已使命中，第一步即返回。新名称计划不介入 NPC 专属特性的怪物身份匹配。

GPS 初始化目录可能晚于 `cprReady` 完成。适配层不缓存原生查找的未命中结果，每次 Medkit 查找都会再询问原入口。Truesight 目录通知自动触发刷新；外部译表更换后仍需要重载或显式 `api.refresh()`；快照重建期间及重建失败后不使用旧计划补充候选。

`api.stop()` 使本客户端的包装失效。若入口仍是本插件安装的函数，恢复安装前的函数；若其他插件随后包装了入口，则保留其函数，只让本插件在链中透传。加载期间停止不会在异步完成后重新装入包装。正常模块启停以重载为边界。

## 当前接入范围与验证边界

GPS 第一版接入 Medkit 使用的公开 `getAllAutomations`，不扩展 `getPreferredAutomation`、`getAppliedOrPreferredAutomation` 内部的闭包调用，不改宏执行路径，也不处理其他第三方自动化来源。GPS 适配需要 CPR，但不需要 CPR 中文别名适配。若未来要支持 GPS 的其他调用方，应另行沿调用路径核对接口。

核心纯计算、适配层的失败与作用域隔离、初始化与停止、安装包结构均由自动测试覆盖。本机源码回放只执行查找函数，并以夹具提供合集、配置和文档身份；部署后的不同客户端、真实模块组合和实际窗口交互仍需单独验证。
