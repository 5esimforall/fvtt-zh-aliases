# 共享基座与三个适配插件

## 共享什么，隔离什么

中文显示名与英文查找名之间的证据可供多个自动化来源使用，但各提供方的候选目录、查找范围和注册入口不同。因此各适配插件共享解析过程，不共享一张输出映射表。产品目标见 [设计](../DESIGN.md)，安装、命令和报告字段见 [README](../README.md)。

| 插件 | 输入 | 输出与外部副作用 |
| --- | --- | --- |
| `truesight` | Quick Insert 可见索引、来源、世界共享审核、可选译表与原名、适配层候选 | 审核成员关系、只读名称快照、计划与诊断；GM 管理世界共享审核，消费端按原生权限读取结果 |
| `cpr-zh-aliases` | 基座快照、CPR 配置与宏名称、既有映射 | 将全局无歧义新增名称写入本客户端 `CONFIG.chrisPremades.renamedItems`，同时向共享查询路由注册按代际／类别／条目消歧的 CPR 名称解析 |
| `gps-zh-aliases` | 基座快照、GPS 合集目录、CPR 的 GPS 集成模式 | 向共享查询路由注册 GPS 名称解析，仅补回缺少的 GPS 候选 |
| `misc-zh-aliases` | 基座快照、MISC 合集目录、文件夹与 factory 配置、CPR 的 MISC 集成模式 | 向同一路由注册 MISC 名称解析，仅补回缺少的 MISC 候选 |

三个名称适配只导入自己目录中的文件，通过 `game.modules.get("truesight").api.names` 调用基座。名称层没有自动化提供方依赖或协议字段；聚类层沿用原有索引自动化标记作为展示元数据，不调用提供方代码。CPR 标识、宏表、GPS/MISC 合集清单和来源模式均在各适配插件内解释。基座和三个适配发行包可以独立解压，三个适配插件只依赖基座和各自实际需要的上游模块。

## 基座接口与快照

共享基座的源码、独立测试和发行工具位于同级 [Truesight 项目](../../truesight/README.md)。公共接口与名称快照契约见 [Truesight 架构](../../truesight/docs/architecture.md)，适配层只接受兼容的 API v1。

## CPR 适配

CPR 适配在 `cprReady` 后读取 CPR 实际配置的合集 ID，尊重可见性与 `thirdParty` 设置。通过 CPR 宏表解释 `flags.chris-premades.info.identifier`，这与 `system.identifier` 是不同字段。CPR 动作译表也由该适配层追加到共同译表来源，而非写死在基座中。

CPR 的全局映射入口是一张扁平显示名表，因此其全局计划保持跨代际、跨类型一致，避免误导直接查找；所有输入加载和计划生成完成后才原子替换自己拥有的键，已有外部映射及原生名称保留。初始化失败时撤回己方键。同时，控制器通过共享查询路由注册作用域为 CPR、按规则代际／特性类别／角色类型与条目自身证据（`_stats.compendiumSource` 所属组、`originalName`、`system.identifier`、完整双语名）消歧的 Medkit 与外部状态后备查找，使同名跨类或跨代际能力（如「狂暴」「偷袭」「动作如潮」「拨挡攻击」「圣疗」）无需牺牲全局安全性即可命中对应自动化。停用或 `api.stop()` 会同时撤回 `renamedItems` 中己方键并恢复查询路由。审核通知自动刷新，异步过期构建不再写入。

## 共享查询与外部状态

CPR 1.5.49 的 Medkit 通过公开的 `getAllAutomations` 查询候选，菜单图标和 Tidy 标题栏通过 `getPreferredAutomation` 判断是否有可用自动化。后者在内部调用闭包中的原始函数，单独包装公开的 `getAllAutomations` 无法让外部提示同步。因此三个公开查询入口由同一个路由连接，而非分别实现中文名称判断。

| 公开入口 | 路由行为 |
| --- | --- |
| `getAllAutomations` | 先执行原查找，仅对缺少的注册来源使用其独立名称计划重试，按来源收取结果并合并排序。 |
| `getPreferredAutomation` | 从当前公开的完整候选查询取得第一项文档，与 Medkit 使用同一套候选。 |
| `getAppliedOrPreferredAutomation` | 未应用来源时使用完整候选；已有来源时先保留原生结果，仅在该来源查找失败且已注册时补查同一来源，不切换到其他提供方。自定义或未适配来源保留原行为。 |

重试使用只读名称视图，保留原文档的方法接收者、嵌套数据、显示名及标识。一次调用中，相同英文查找名只询问原入口一次，各提供方只收取自己的结果；原查找已有该来源时不重试。候选文档、UUID、版本和 `priority` 均由 CPR 返回。合并按原生 `priority` 升序排列；同优先级时原生候选在前并保留原顺序，新增候选按 CPR 的来源配置顺序排列，不依赖插件加载顺序。

路由不缓存跨调用的未命中结果。重试结束前再次检查注册状态与名称计划，停止、权限撤回或证据刷新期间不发布旧候选。原生查找异常继续抛出，别名解析或重试异常只记录到对应适配的 `lastLookupError` 并保留原结果。首选查询在调用时读取公开的候选入口，以保留之后安装的外部包装。

共享实现维护在本仓库 `shared/`：`adapter-runtime.mjs` 负责作用域、计划与刷新生命周期，`medkit-lookup.mjs` 负责查询入口和候选合并。GPS/MISC 的 `runtime.mjs` 仅提供目录函数、来源 ID、入口和模式设置；目录规则仍属于各提供方。Truesight 继续只提供名称证据，不包含 CPR 协议或查询包装。

构建将共享实现生成到各插件的 `scripts/shared/`，安装包无跨插件源码导入。两份运行代码通过 CPR 命名空间上的私有 `Symbol.for('fvtt-zh-aliases.medkit-lookup.v1')` 注册协议共用一个路由，第二个适配只注册解析器，不再叠加包装。停用一方仅移除其解析器；最后一方停止时恢复仍由路由持有的函数。其他插件后装的包装不被覆盖，其保留的旧路由转为原生透传。安装写入失败会撤回已安装入口；不存在的可选状态入口不会被凭空添加。已应用来源入口还要求 CPR 的 `itemUtils.getSource`，缺失时保留该入口原样。

## GPS 适配

GPS 使用 `getGPSAutomation` 作为必要的上游能力检查，目录按 CPR 的 `gambitPremades` 模式纳入常规、自制与第三方合集，按合集后缀区分规则代际。官方 aliases 已使命中时，共享路由保留该原生候选。初始化目录晚于 `cprReady` 完成时，后续查询会继续询问原入口；不介入 NPC 专属特性的怪物身份匹配。

## MISC 适配

MISC 使用 `getMISCAutomation` 作为必要的上游能力检查，按 `miscPremades` 模式读取六种常规合集及自制 Items、UA Spells 文件夹，排除配置中的 factory 条目。常规与自制目录按合集后缀区分代际，UA 法术按行内 `system.source.rules` 区分。文件夹与 factory 配置属于 MISC 适配上下文，名称对和歧义判断仍由基座提供。上游 UA 职业特性路径及 NPC 身份边界见 [使用说明](../README.md#名称怎样匹配)。

## 当前接入范围与验证边界

共享路由接入上表三个公开查询入口，不改写 CPR 内部闭包、自动化应用处理、宏执行或 `isUpToDate` 的版本判断。未应用物品的可用提示消费同一候选查询，已应用物品仍使用 CPR 原有的状态颜色。GPS/MISC 均需要 CPR，但互不依赖，也不需要 CPR 中文别名适配。

自动测试覆盖独立及联合启用、停止恢复、来源优先级、已应用来源、错误回退和独立打包。本机源码回放执行 CPR 查询函数、Medkit 准备数据、标题菜单与 Tidy 状态函数，合集、文档和界面元素由内存夹具提供；它不能替代部署后真实客户端的实机验收。

## 证据变更

CPR、GPS、MISC 只对 Truesight 的名称、身份、权限、来源或审核领域变更重建计划；图片等纯目录展示变化不撤回别名。变更通知必须携带 `changes` 领域集合。

各适配器通过 `names.createRefreshQueue` 合并刷新：本地条目增删改名等非撤权刷新在构建期间保留当前有效映射与作用域计划，新快照校验通过后再原子替换（并过滤自身已拥有的键后再比对外部别名）；权限变更或状态失效触发 `{retract: true}` 时同步撤回旧结果，构建失败也立即撤回。最多一个构建在运行，连续变化只保留一次最新重建。发布前同时检查任务令牌和快照有效性；查找阶段通过 `isAccessCurrent()` 检查权限与可见合集是否仍有效。字段加载可以共享，计划、作用域和已有别名处理保持提供方独立。
