# 共享基座与三个适配插件

## 共享什么，隔离什么

中文显示名与英文查找名之间的证据可供多个自动化来源使用，但各提供方的候选目录、查找范围和注册入口不同。因此各适配插件共享解析过程，不共享一张输出映射表。产品目标见 [设计](../DESIGN.md)，安装、命令和报告字段见 [README](../README.md)。

| 插件 | 输入 | 输出与外部副作用 |
| --- | --- | --- |
| `truesight` | Quick Insert 可见索引、来源、客户端审核、可选译表与原名、适配层候选 | 审核成员关系、只读名称快照、计划与诊断；仅保存自身客户端审核 |
| `cpr-zh-aliases` | 基座快照、CPR 配置与宏名称、既有映射 | 将完整计划中的新增名称写入本客户端 `CONFIG.chrisPremades.renamedItems` |
| `gps-zh-aliases` | 基座快照、GPS 合集目录、CPR 的 GPS 集成模式 | 包装 Medkit 调用的查找入口，仅补回原结果缺少的 GPS 候选 |
| `misc-zh-aliases` | 基座快照、MISC 合集目录、文件夹与 factory 配置、CPR 的 MISC 集成模式 | 包装同一入口，仅补回原结果缺少的 MISC 候选 |

三个名称适配只导入自己目录中的文件，通过 `game.modules.get("truesight").api.names` 调用基座。名称层没有自动化提供方依赖或协议字段；聚类层沿用原有索引自动化标记作为展示元数据，不调用提供方代码。CPR 标识、宏表、GPS/MISC 合集清单和来源模式均在各适配插件内解释。基座和三个适配发行包可以独立解压，三个适配插件只依赖基座和各自实际需要的上游模块。

## 基座接口与快照

共享基座的源码、独立测试和发行工具位于同级 [Truesight 项目](../../truesight/README.md)。公共接口与名称快照契约见 [Truesight 架构](../../truesight/docs/architecture.md)，适配层只接受兼容的 API v1。

## CPR 适配

CPR 适配在 `cprReady` 后读取 CPR 实际配置的合集 ID，尊重可见性与 `thirdParty` 设置。通过 CPR 宏表解释 `flags.chris-premades.info.identifier`，这与 `system.identifier` 是不同字段。CPR 动作译表也由该适配层追加到共同译表来源，而非写死在基座中。

CPR 的出口是一张全局显示名表，因此计划使用全局作用域。所有输入加载和计划生成完成后才注册，已有映射及原生名称保留。初始化失败时不会写入部分计划。停用并重载撤去本插件提供的新增映射；`api.refresh()` 撤下自己发布的旧键再重建，`api.stop()` 撤回自己仍持有的键；其他插件后续改写的键保留。审核通知自动刷新，异步过期构建不再写入。

## GPS 适配

本机 CPR 1.5.49 的 source map 显示，Medkit 通过公开的 `compendiumUtils.getAllAutomations` 查询候选。该函数内部按来源分别调用查找函数；GPS 分支读取其闭包中的目录，而不是 CPR 的 `renamedItems`。只替换公开对象上的 `getGPSAutomation`，无法改变该内部闭包调用。

GPS 适配因此包装公开对象的 `getAllAutomations`，不导入或修改 CPR 的私有集成目录：

1. 原样执行原生查找，原生 GPS 候选存在时直接返回。
2. 根据提供方启用状态、类型、规则代际和当前 GPS 集成模式，查询独立的名称计划。
3. 只在计划有唯一英文名时，以只读名称视图重试原生入口。原物品、嵌套数据和方法接收者保持原有对象，未调用文档更新或自动化应用。
4. 只收取重试结果中的 `gambits-premades` 来源，保留原有其他提供方结果，再按原生返回的优先级排序。版本、文档 UUID 和候选选择仍由原入口决定。

GPS 的目录按 CPR 集成使用的合集清单和 `gambitPremades` 模式读取，规则代际按其合集后缀区分。模式变化采用新计划，已有原生结果始终优先。适配层不修改官方 aliases；它们若已使命中，第一步即返回。新名称计划不介入 NPC 专属特性的怪物身份匹配。

GPS 初始化目录可能晚于 `cprReady` 完成。适配层不缓存原生查找的未命中结果，每次 Medkit 查找都会再询问原入口。Truesight 目录通知自动触发刷新；外部译表更换后仍需要重载或显式 `api.refresh()`；快照重建期间及重建失败后不使用旧计划补充候选。

`api.stop()` 使本客户端的包装失效。若入口仍是本插件安装的函数，恢复安装前的函数；若其他插件随后包装了入口，则保留其函数，只让本插件在链中透传。加载期间停止不会在异步完成后重新装入包装。正常模块启停以重载为边界。

## MISC 适配

MISC 沿用 GPS 的原生优先、只读名称重试和按来源收取结果的接入方式，但独立维护计划与生命周期。它调用同一 Truesight 名称接口，不依赖 CPR 或 GPS 中文适配，也不把自身查找规则放入共享基座。入口必须同时具备 `getAllAutomations` 与 `getMISCAutomation`，缺失时报告 `unsupported-misc-entry` 并保留原查找。

目录读取六种常规合集，并按 CPR 的 `miscPremades` 模式纳入自制 Items 与 UA Spells 文件夹；排除 MISC 配置中 factory 条目。常规与自制目录按合集后缀区分代际，UA 法术按行内 `system.source.rules` 区分。上游 UA 职业特性路径的限制见 [使用说明](../README.md#名称怎样匹配)。文件夹 ID 和 factory 配置是适配层上下文，名称对、审核分组与歧义判断仍由基座提供。

MISC 与 GPS 包装可按任意顺序安装。每层只补回自己的来源，停用其中一层不撤销另一层的结果；当后续包装仍保留旧函数时，停止的层只透传。三个名称适配均保留上游已有的名称映射与候选。

## 当前接入范围与验证边界

GPS 与 MISC 接入 Medkit 使用的公开 `getAllAutomations`，不扩展 `getPreferredAutomation`、`getAppliedOrPreferredAutomation` 内部的闭包调用，不改宏执行路径，也不处理其他第三方自动化来源。GPS 与 MISC 适配需要 CPR，但不需要 CPR 中文别名适配。若未来要支持其他调用方，应另行沿调用路径核对接口。

核心纯计算、适配层的失败与作用域隔离、初始化与停止、安装包结构均由自动测试覆盖。本机源码回放执行查找函数及 MISC 目录初始化，并以夹具提供合集、配置和文档身份；部署后的不同客户端、真实模块组合和实际窗口交互仍需单独验证。

## 证据变更

CPR、GPS、MISC 只对 Truesight 的名称、身份、权限、来源或审核领域变更重建计划；图片等纯目录展示变化不撤回别名。无领域信息的旧 API v1 通知按完整变化处理。
